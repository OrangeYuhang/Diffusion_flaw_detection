# DefectDiffu 实验执行方案

## 0. 环境与前置条件

### 0.1 依赖

- **anomalib 2.4.1** — 已安装在 `anodetection` conda 环境 (`D:\anaconda\envs\anodetection`)
- **PIL** — 传统数据增强用（DefectDiffu 环境已有）

> **重要：** 所有 `eval` 和 `run-all` 命令必须在 `anodetection` 环境下执行。
> `prepare` 命令可在任意 Python 环境下运行（无需 anomalib）。

### 0.2 数据概况

```
anodetection/data/mvtec/

  test/{class}/{defect}/  1,725 测试图像（MVTec 标准结构）
  ground_truth/{class}/{defect}/  1,258 像素级掩码
```

15 类别: bottle, cable, capsule, carpet, grid, hazelnut, leather, metal_nut, pill, screw, tile, toothbrush, transistor, wood, zipper

### 0.3 快速开始

```bash
# 激活 anodetection 环境（后续所有 eval/run-all 命令都在此环境下）
conda activate anodetection

# Step 1: 准备所有实验数据目录（任意 Python 环境均可）
python ./anodetection/experiments/run_experiments.py prepare \
  --data ./anodetection/data/mvtec \
  --workdir ./anodetection/experiments/output

# Step 2: 查看生成的实验清单
cat ./anodetection/experiments/output/experiment_manifest.json

# Step 3: 逐实验配置评估（在 anodetection 环境下）
python ./anodetection/experiments/run_experiments.py eval \
  --exp-dir ./anodetection/experiments/output/exp1_fewshot/N5_M50

# 或批量运行全部（耗时较长，约 3-5 分钟/配置 × 15 类）
python ./anodetection/experiments/run_experiments.py run-all \
  --workdir ./anodetection/experiments/output

# 指定其他模型（默认 patchcore）
python ./anodetection/experiments/run_experiments.py eval \
  --exp-dir ./anodetection/experiments/output/exp1_fewshot/N5_M50 \
  --model efficient_ad

# RTX 5070 等新 GPU 如遇到 CUDA kernel 不兼容，用 CPU 模式：
python ./anodetection/experiments/run_experiments.py eval \
  --exp-dir ./anodetection/experiments/output/exp1_fewshot/N5_M50 --device cpu
```

### 0.4 种子与可复现性

数据采样固定 `random.seed(42)`。评估时通过 `--seed` 参数控制（默认 42），每个实验配置应独立运行 3 次取均值 ± 标准差。

### 0.5 PatchCore 的 ONE_CLASS 特性

PatchCore 的 `learning_type = ONE_CLASS`，**训练阶段仅使用 `train/good/` 中的正常样本**构建 coreset，不会读取 `train/bad/`。

这意味着：
- **Experiment 1-4 的 "real_only" vs "Ours" 对比**：对于 PatchCore，两组的 `train/good/` 内容完全相同（都是 N 张正常样本），`train/bad/` 中的合成缺陷不会被 PatchCore 使用。**实测结果验证了这一点**：各组 "real_only" 与 "Ours" 的 Average AUROC 差值极小（N1: +0.028, N5: +0.004, N10: −0.009），主要由随机采样方差导致，非合成缺陷贡献。
- **要让合成缺陷发挥作用**，需切换到支持监督训练的模型（如 `efficient_ad`、`draem`），通过 `--model` 参数指定。监督模型评估前，`run_experiments.py` 会自动将 `synthetic/` 合并为 `train/bad/`。
- 合成缺陷数据存放在各实验目录下的 `synthetic/{class}/` 平行目录中，与原生 MVTec 结构互不干扰。

## 9. 有效结果判据

- [ ] N=1 + synthetic 的 Image AUROC > N=1 real only + 0.15 → **未达成**（增益仅 +0.028，从 0.817→0.845）。合成缺陷在极端 few-shot 场景下增益有限
- [x] N=5 + synthetic 接近或超过 N=10 real only → **部分达成**（N5+syn=0.902 ≈ N10 real=0.918，差距 0.016）
- [x] 实验五中 medium CFG 优于 low 和 high → **达成**（medium=0.908, low=0.893, high=0.897）
- [x] 传统增强对 pixel-level 指标的提升远小于 Ours → **与预期相反**：传统增强 Image AUROC=0.937 显著优于 Ours=0.896。原因：传统增强作用于 train/good/（正常样本），实际增加了 coreset 多样性；合成缺陷在 train/bad/ 中，PatchCore 根本不读取
- [ ] 至少 3 个长尾缺陷的检测率在加入合成样本后提升 > 0.10 → **未达成**（长尾类别中最大增益为 grid: +0.021, screw: +0.011）。Δ 均值仅 +0.0021

### 关键发现

1. **PatchCore 无法利用合成缺陷**：real_only vs Ours 的表观差异主要由不同采样的 train/good 导致，不是合成缺陷的贡献。这与文档第 0.5 节的分析一致。
2. **传统数据增强是最强基线**：对正常样本做 rotation/flip/color jitter 直接增强 coreset → Image AUROC 从 0.893 提升到 0.937。
3. **合成缺陷在监督模型中才能发挥作用**：要验证 DefectDiffu 的价值，需用 `efficient_ad` 或 `draem`（利用 train/bad）重新评估关键配置。
