# DefectDiffu 实验执行方案

## 0. 环境与前置条件

### 0.1 依赖

- **anomalib 2.4.1** — 已安装在 `anodetection` conda 环境 (`D:\anaconda\envs\anodetection`)
- **PIL** — 传统数据增强用（DefectDiffu 环境已有）

> **重要：** 所有 `eval` 和 `run-all` 命令必须在 `anodetection` 环境下执行。
> `prepare` 命令可在任意 Python 环境下运行（无需 anomalib）。

### 0.2 数据概况

```
anodetection/data/mvtec/
  train/good/         3,629 真实正常样本（所有类混合，文件名 {class}_xxx.png）
  train/bad/          1,606 缺陷样本（730 真实 + 876 合成，含 CFG scale 标识）
  test/{class}/{defect}/  1,725 测试图像（MVTec 标准结构）
  ground_truth/{class}/{defect}/  1,258 像素级掩码
```

15 类别: bottle, cable, capsule, carpet, grid, hazelnut, leather, metal_nut, pill, screw, tile, toothbrush, transistor, wood, zipper

**合成缺陷数量（每类，仅 train/bad 中合成部分）：**

| 类别 | 合成数 | 类别 | 合成数 | 类别 | 合成数 |
|------|:---:|------|:---:|------|:---:|
| bottle | 36 | grid | 60 | toothbrush | 12 |
| cable | 96 | hazelnut | 48 | transistor | 48 |
| capsule | 60 | leather | 60 | wood | 60 |
| carpet | 60 | metal_nut | 48 | zipper | 84 |
| pill | 84 | screw | 60 | tile | 60 |

> 注意：toothbrush 合成缺陷最少（12），cable 最多（96）。实验中 M 值不能超过各类的实际可用数量。

### 0.3 快速开始

```bash
# 激活 anodetection 环境（后续所有 eval/run-all 命令都在此环境下）
conda activate anodetection

# Step 1: 准备所有实验数据目录（任意 Python 环境均可）
python experiments/run_experiments.py prepare \
  --data ./anodetection/data/mvtec \
  --workdir ./experiments/output

# Step 2: 查看生成的实验清单
cat ./experiments/output/experiment_manifest.json

# Step 3: 逐实验配置评估（在 anodetection 环境下）
python experiments/run_experiments.py eval \
  --exp-dir ./experiments/output/exp1_fewshot/N5_M50

# 或批量运行全部（耗时较长，约 3-5 分钟/配置 × 15 类）
python experiments/run_experiments.py run-all \
  --workdir ./experiments/output

# 指定其他模型（默认 patchcore）
python experiments/run_experiments.py eval \
  --exp-dir ./experiments/output/exp1_fewshot/N5_M50 \
  --model efficient_ad

# RTX 5070 等新 GPU 如遇到 CUDA kernel 不兼容，用 CPU 模式：
python experiments/run_experiments.py eval \
  --exp-dir ./experiments/output/exp1_fewshot/N5_M50 --device cpu
```

### 0.4 种子与可复现性

数据采样固定 `random.seed(42)`。评估时通过 `--seed` 参数控制（默认 42），每个实验配置应独立运行 3 次取均值 ± 标准差。

### 0.5 PatchCore 的 ONE_CLASS 特性

PatchCore 的 `learning_type = ONE_CLASS`，**训练阶段仅使用 `train/good/` 中的正常样本**构建 coreset，不会读取 `train/bad/`。

这意味着：
- **Experiment 1-4 的 "real_only" vs "Ours" 对比**：对于 PatchCore，两组的 `train/good/` 内容完全相同（都是 N 张正常样本），结果将一致。`train/bad/` 中的合成缺陷不会被 PatchCore 使用。
- **要让合成缺陷发挥作用**，需切换到支持监督训练的模型（如 `efficient_ad`、`draem`），通过 `--model` 参数指定。

实验中 `train/bad/` 目录会被创建，确保切换到监督模型时可直接使用。

## 1. 实验一：不同 few-shot 规模下的增益

### 1.1 目的

验证 DefectDiffu 生成样本在少样本场景下的价值。核心假设：**真实样本越少，合成样本的增益越大**。

### 1.2 实验配置

| 配置名称 | 真实正常样本/类 | 合成缺陷/类 | 说明 |
|----------|:---:|:---:|------|
| `full_real_baseline` | 全部 | 0 | A 组：上界参考 |
| `N1_real_only` | 1 | 0 | B 组：极端 few-shot |
| `N1_M50` | 1 | 50 | C 组：Ours |
| `N2_real_only` | 2 | 0 | |
| `N2_M50` | 2 | 50 | |
| `N5_real_only` | 5 | 0 | |
| `N5_M50` | 5 | 50 | |
| `N10_real_only` | 10 | 0 | |
| `N10_M50` | 10 | 50 | |

共 9 个配置。

### 1.3 运行

```bash
# 在 anodetection 环境下执行
python experiments/run_experiments.py prepare --data ./anodetection/data/mvtec \
  --workdir ./experiments/output --experiments exp1

# 对每个配置运行 3 次（不同 seed）
for seed in 42 123 456; do
  python experiments/run_experiments.py eval \
    --exp-dir ./experiments/output/exp1_fewshot/N5_M50 --seed $seed

# 如使用监督模型（利用 train/bad 中的合成缺陷）：
```

## 8. 故障排查

| 问题 | 原因 | 解决 |
|------|------|------|
| `import anomalib` 失败 | 不在 anodetection 环境 | `conda activate anodetection` |
| `MVTecAD` 路径错误 | 数据目录结构不标准 | 检查 `{class}/train/good/` 是否非空 |
| PatchCore 返回全 0.5 AUROC | `train/good/` 无图片或太小 | 确认每类至少有 1 张正常样本 |
| 传统增强报错 | PIL 未安装 | `pip install Pillow` |
| `_copy_dir` 失败 | 权限不足 | 脚本直接复制，无需符号链接 |
| 内存不足 | PatchCore coreset 太大 | 考虑设置 `coreset_sampling_ratio` |
