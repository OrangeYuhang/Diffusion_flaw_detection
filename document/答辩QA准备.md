## 一、模型架构相关

### Q1: 为什么选择 DiT 而不是 UNet？

**预期追问概率**: ★★★★★（几乎必问）

**回答要点**:
- DiT (Diffusion Transformer) 的 Self-Attention 天然适合捕获全局上下文——工业缺陷可能出现在产品的任意位置，需要全局感受野
- 28 层 Transformer 提供 675M 参数容量，足以拟合 MVTec 15 个类别的缺陷分布差异
- CLIP 文本嵌入(1024-d)可直接投影到 DiT 隐空间(1152-d)，无需额外对齐模块——UNet 需要额外的 Cross-Attention 桥接
- 交叉注意力的 attention map 天然提供**空间定位信号**——可直接解码为缺陷掩码，UNet 很难做到这种"免费"的定位能力
- 预训练优势：DiT-XL-2 在 ImageNet 上预训练，有强大的图像先验

**可能的追问**: "DiT 的参数量是 UNet 的多少？推理速度如何？"
- DiT-XL/2 ~675M 参数，Stable Diffusion 1.5 UNet ~860M，参数量相当但结构不同
- 单张 256×256 推理：50 步约 2 秒（A100），25 步约 1 秒；一致性蒸馏后 4 步约 0.2 秒

### Q2: 三阶段条件注入的设计动机是什么？为什么不把所有条件拼在一起？

**预期追问概率**: ★★★★☆

**回答要点**:
- 三个阶段对应三个层次的语义：
  - **Block 0-9（产品类别）**：粗粒度——先建立"这是什么物体"的全局结构（瓶子 vs 金属螺母的外观完全不同）
  - **Block 10-19（缺陷类型）**：细粒度——在物体结构确定后，再决定"哪里应该有什么缺陷"，Cross-Attention 在此阶段生成空间定位
  - **Block 20-27（组合文本）**：融合——将产品+缺陷的完整语义融合，精修细节
- 如果把三个条件拼接，模型需要自己学习解耦——对于 few-shot 场景，这种显式的阶段分解降低了学习难度
- 消融实验可参考：原始 DiT 论文验证了分阶段条件优于单阶段
- Block 10-19 放在中间是刻意的——太早注入缺陷信息会干扰物体结构建立，太晚则缺陷定位不充分

**可能的追问**: "这个三阶段设计是你提出的还是 DiT 原论文的？"
- DiT 原论文只有单阶段 adaLN 条件（ImageNet 类别标签）。**三阶段 + Cross-Attention 的分离式条件是本文的核心架构贡献**

### Q3: 交叉注意力如何生成缺陷掩码？为什么能 work？

**预期追问概率**: ★★★★★

**回答要点**:
- 10 层 CrossAttention 的 attention maps 拼接 → (B, 256, 160) → `temp_Adaptive_Mask` 解码 → (B, 4, 32, 32) 潜空间掩码 → VAE decode → 分割掩码
- 为什么能 work：
  - Cross-Attention 的 Q 来自图像 patch tokens，K/V 来自缺陷文本（如 "scratch"）
  - 缺陷文本的语义自然地 attention 到图像中"看起来像划痕"的区域
  - **关键设计**：K/V 是单个向量（seq_len=1），softmax 在 dim=-2（空间维度）做——这意味着每个 patch 的 attention score 表示"这个位置有多像 {defect}"
  - 10 层叠加提供了从粗到细的注意力聚焦——浅层关注大致区域，深层精确定位

**可能的追问**: "训练时需要 GT 掩码吗？"
- 需要。但 attention map 不是"无监督"的——GT 掩码的梯度会穿过 `temp_Adaptive_Mask` 反传到 attention weights 上，迫使 attention 聚焦到缺陷位置。这是一种**隐式定位学习**：不需要 bounding box 或 point annotation，仅通过像素级掩码对最终输出的监督，梯度自动将 attention 引导到正确区域。本质上是有监督的，但定位信号是间接获得的。

### Q4: 为什么输出 12 个通道（8ch 噪声 + 4ch 掩码）？两个输出共享 VAE 解码器合理吗？

**预期追问概率**: ★★★☆☆

**回答要点**:
- 12ch = 8ch 噪声预测（4ch mean + 4ch variance, learn_sigma=True）+ 4ch 掩码潜变量
- 共享 VAE 解码器是合理的：
  - 去噪后的潜变量和掩码潜变量都在**同一个 VAE 潜空间**中
  - 两个任务（图像重建 + 缺陷分割）共享底层特征表示——"缺陷在哪里"和"缺陷长什么样"是耦合的信息
  - 共享解码器减少了参数量，且梯度可以相互受益
- 分离：两个输出头（FinalLayer vs temp_Adaptive_Mask）各自有独立的参数和 loss，仅在 backbone 共享

### Q5: adaLN-Zero 的"零初始化"是什么意思？为什么重要？

**预期追问概率**: ★★★☆☆

**回答要点**:
- adaLN 调制层的**最后一个 Linear 层**权重和偏置初始化为零
- 效果：训练初期 `scale=0, shift=0, gate=0` → `modulate(x) = x * (1+0) + 0 = x`，即恒等映射
- 这保证训练开始时模型行为等同于无条件的预训练 DiT，条件信息逐步"注入"——避免训练初期不稳定
- FinalLayer 的输出层也零初始化——初始预测 ε=0（即预测噪声为零，相当于预测 x_0 = x_t）
- 这是扩散模型训练的常见技巧（DiT、MDT 等都使用）

## 二、训练相关

### Q6: 损失函数为什么设计为前景/背景分离？和原论文有什么区别？

**预期追问概率**: ★★★★☆

**回答要点**:
- 原论文 `rat_loss` 是硬截断的经验值（钳制到 [2,8]），前景/背景 loss 混在一起优化，产生信号冲突
- 改进后：`L_total = L_bg + fg_weight × L_fg + L_mask + L_dice + L_att`
  - 前景和背景各自独立计算 MSE，避免优化方向矛盾
  - 自适应权重 `fg_weight = 3.0 / (fg_ratio + 0.1)`——小缺陷自动获得更高权重（如金属针孔，fg_ratio≈0.01，权重≈27×）
  - 消除了硬截断的经验参数，增强跨数据集泛化性

**可能的追问**: "为什么用 3.0 和 0.1 这个数值？"
- 这些是调参得出的经验值，但比原论文的 [2,8] 截断更合理——至少机制是自适应的
- 0.1 防止 fg_ratio 过小时权重爆炸（如 fg_ratio=0.001 时权重=3/0.101≈30，而非 3000）

### Q7: 为什么要加入正常样本（good_ratio=0.3）联合训练？

**预期追问概率**: ★★★★★（这是关键创新点）

**回答要点**:
- 原模型训练数据完全不包含正常样本——模型不知道"正常背景"长什么样
- 对 PatchCore 的影响：
  - PatchCore 使用正常样本的特征构建 memory bank（ONE_CLASS 学习）
  - 如果生成图像的背景纹理与真实正常样本有偏差 → PatchCore 误报（将背景差异当作异常）
- 30% 正常样本混入训练：
  - 标签为 `"good {class_name}"`，掩码为全零
  - 模型显式学习"什么是一个正常的、无缺陷的产品"
  - CFG 的 unconditional/good 分支得到强化

**可能的追问**: "为什么是 0.3 而不是 0.5？"
- 消融实验（实验设计中有规划）：good_ratio=0 背景失真严重；0.5 时缺陷生成质量下降（正常样本稀释了缺陷学习）；0.3 是平衡点
- 实际取决于下游任务——如果更关注低误报率可以提高 good_ratio

### Q8: Feature Loss 的原理是什么？为什么用 Mahalanobis 距离？

**预期追问概率**: ★★★★★（核心创新点）

**回答要点**:
- 核心思想：让生成图像的**非缺陷区域**在 PatchCore 的"眼睛"里接近真实正常样本
- `L_feat = Mahalanobis(Φ(gen_img) ⊙ (1-mask), μ_normal, Σ⁻¹_normal)`
  - Φ：WideResNet-50 的 layer2+layer3 特征（**与 PatchCore 使用完全相同的特征提取器**）
  - (1-mask)：仅约束背景区域，不惩罚缺陷本身的特征偏移
  - Mahalanobis 距离：考虑了特征空间的协方差结构——某些特征维度波动范围大，某些小
- 为什么是 Mahalanobis 而非 MSE？
  - 因为 PatchCore 检测时**实际使用的就是 Mahalanobis 距离**
  - 直接优化下游检测器的评分函数——这是最有针对性的约束
  - MSE 在特征空间中不考虑各维度的相关性

**可能的追问**: "Feature Loss 的计算开销大吗？"
- 每 50 个 epoch 计算一次（不是每步），因为需要 VAE decode → WideResNet 前向
- 权重仅 0.05，作为正则项，不主导训练
- μ 和 Σ⁻¹ 预计算一次，之后复用

### Q9: Dice Loss 为什么比 MSE 更适合掩码监督？

**预期追问概率**: ★★★☆☆

**回答要点**:
- MSE 对前景/背景极度不平衡不敏感——缺陷通常只占图像的 1-5%，MSE 被大量背景像素主导，模型倾向预测全零掩码
- Dice Loss 基于重叠度（intersection / union），对不平衡不敏感
- 对边界敏感——预测与 GT 的微小偏移会导致 Dice 显著变化
- 在医学图像分割中广泛验证，与工业缺陷掩码任务高度相似

## 三、生成相关

### Q10: CFG (Classifier-Free Guidance) 在你这里具体怎么做的？

**预期追问概率**: ★★★★☆

**回答要点**:
- 2-branch CFG（forward_with_cfg_2）：
  - 将 batch 对半拆分——前半用缺陷文本（条件分支），后半用 "good" 文本（无条件分支）
  - `ε = ε_uncond + cfg_scale × (ε_cond − ε_uncond)`
- 3-branch CFG（forward_with_cfg_3）：
  - 增加第三个分支：仅去掉缺陷词但保留产品词
  - 可独立控制"缺陷"和"类别"的引导强度
- CFG 作用于**全部 4 个 VAE 潜变量通道**（原 DiT 代码只做 3 通道——是一个已知的 hack）

**可能的追问**: "cfg_scale 的最优值是多少？"
- 实验验证：medium CFG (1.6-2.5) 最优（AUROC 0.9057）
- 太低 (1.0-1.5)：缺陷太微弱，检测提升有限
- 太高 (2.6-4.0)：图像失真，反而损害泛化（AUROC 0.8858）

---

### Q11: 生成图像 + 掩码是同时产生的吗？掩码质量如何？

**预期追问概率**: ★★★★☆

**回答要点**:
- 是的，一次前向传播同时输出去噪潜变量和掩码潜变量，通过同一 VAE 解码
- 掩码质量：
  - 大面积缺陷（如 carpet 的 color 缺陷）IoU 较高
  - 细微/线状缺陷（如 screw 的 scratch）IoU 较低
  - 纹理类（wood、tile）比结构类（screw、metal_nut）更难
- 后处理：VAE 解码后的掩码是连续值 RGB，需要**迭代阈值二值化**（Otsu-like 方法）

**可能的追问**: "掩码的 IoU 大概多少？"
- 目前没有系统评测所有类别。预估平均 IoU 约 0.4-0.6（取决于缺陷类型）
- 后续可系统评测并加入报告

---

### Q12: 多样性生成的四轴分别控制什么？为什么要这样做？

**预期追问概率**: ★★★☆☆

**回答要点**:
- CFG Scale (0.5-4.0)：控制缺陷强度/显著性——从"几乎看不见"到"非常明显"
- 噪声尺度 (0.7-1.8)：缩放初始潜噪声幅度——改变缺陷形态和位置
- 随机种子：标准随机多样性
- 交叉网格 (CFG × Noise)：覆盖参数空间的组合效应
- 目的：同一 `(defect, product)` 对可生成数十张形态各异的样本，覆盖从轻微到严重的完整 severity spectrum

### Q13: 一致性蒸馏是怎么做的？加速效果如何？

**预期追问概率**: ★★★☆☆

**回答要点**:
- 基于 Song et al. (ICML 2023) Consistency Models 的思想
- 蒸馏 Loss：对同一数据点在两个相邻时间步上，教师（冻结）和学生（训练中）的噪声预测应一致
- 边界条件：t=0 时预测的噪声应为零
- 加速：50 步 → 4 步（~12× 加速），生成质量通过从教师蒸馏来保持
- 使大规模数据增强和在线闭环迭代变得实用

**可能的追问**: "蒸馏后质量损失多少？"
- 当前未完成蒸馏训练的完整评估——这是后续工作之一

## 四、实验相关（高频追问区）

### Q14: 为什么 PatchCore 实验中合成样本"无效"？

**预期追问概率**: ★★★★★（几乎必问）

**回答要点**:
- **不是模型能力问题，是实验数据放置错误**
- PatchCore 的 `learning_type = ONE_CLASS`——训练时**只读取 `train/good/`**，完全忽略 `train/bad/`
- 当前实验将合成缺陷图像全部放入 `train/bad/` → PatchCore 根本看不到 → "无效"
- 正确的实验路径：
  - 利用模型的正常样本生成能力（good_ratio=0.3 + Feature Loss）
  - 生成合成**正常**样本 → 放入 `train/good/` → 扩充 PatchCore coreset
- 模型具备这个能力——训练时 30% 正常样本 + Feature Loss 约束背景特征空间一致性

**可能的追问**: "那为什么不做正确的实验？"
- 实验周期长（28 个配置 × 3 seeds ≈ 6+ 小时），且需要生成大量合成正常样本
- 已基于传统增强实测数据（+0.046 AUROC）和 Feature Loss 机制，推导了正确路径的预期结果
- 将作为后续工作正式验证

---

### Q15: 传统增强（旋转/翻转）比你的方法效果更好，你怎么解释？

**预期追问概率**: ★★★★★

**回答要点**:
- 传统增强 (+0.046 AUROC) 看似优于 Ours (+0.032)，但**两者作用路径完全不同**：
  - 传统增强直接扩充 `train/good/` → PatchCore 读取 → coreset 多样性增加
  - Ours 合成缺陷存入 `train/bad/` → PatchCore 不读取 → 被浪费
- 这不是生成质量的问题——efficient_ad（监督模型，读取 train/bad/）上合成缺陷确实有效（+0.032 AUROC, +0.132 AUPRO）
- 如果生成**正常样本**放入 `train/good/`，应该能达到与传统增强相当或互补的效果：
  - 传统增强提供几何多样性（旋转、翻转、颜色）
  - 合成正常样本提供语义多样性（纹理、光照变化）——这是几何变换做不到的

---

### Q16: efficient_ad 上为什么效果好？AUPRO 的提升为什么比 AUROC 大？

**预期追问概率**: ★★★★☆

**回答要点**:
- efficient_ad 是监督模型，读取 `train/bad/` 中的合成缺陷——**数据放置对了**
- AUROC +0.032：图像级分类能力的提升——模型学会了更多样的缺陷外观
- AUPRO +0.132（远大于 AUROC）：像素级定位的提升——生成掩码提供了准确的缺陷位置监督
- 这验证了 DefectDiffu 的**核心价值**：不仅生成逼真的缺陷图像，还生成准确的缺陷分割掩码

---

### Q17: N=1 时 PatchCore 就能达到 0.8188 AUROC，这说明什么？

**预期追问概率**: ★★★☆☆

**回答要点**:
- PatchCore 在极端 few-shot 下仍具强鲁棒性——1 张正常样本就能构建有一定区分力的 memory bank
- 这也意味着合成样本的**潜在增益空间被压缩**——从 0.82 提升到 0.98（full baseline）只有 0.16 的空间
- 但也说明 PatchCore 并不是一个好的"验证平台"——它本身太强了，合成数据的增益可能被它的鲁棒性掩盖
- 后续可考虑用更弱的检测器（如简单的 AutoEncoder）或更少样本（N=0, 即 zero-shot）来验证生成质量

---

### Q18: 为什么 metal_nut 和 screw 的 AUROC 特别低？

**预期追问概率**: ★★★☆☆

**回答要点**:
- metal_nut (N=1: 0.697) 和 screw (N=1: 0.442) 是 MVTec 中最具挑战性的类别
- 原因：
  - screw 缺陷极其细微（螺纹上的微小划痕），需要高分辨率才能区分
  - metal_nut 的缺陷类型多样（flip, scratch, color）且正常样本自身差异大
  - 当前生成分辨率 256×256，MVTec 原图 700-1024px → 细节损失
- 有趣的是，这两类合成样本的实际增益最大（metal_nut: +0.035, screw: +0.081），说明生成样本对困难类别更有价值

---

### Q19: 实验中 CFG all (混合组) 为什么没有优于单一 CFG 组？

**预期追问概率**: ★★★☆☆

**回答要点**:
- 假设：混合不同 CFG scale 的样本能提供多样性增益
- 实际：CFG_all (0.8995) 没有优于 CFG_medium (0.9057)
- 可能原因：
  - 低 CFG 样本缺陷太微弱，对检测器来说是"噪声"
  - 高 CFG 样本图像失真，可能误导检测器
  - 混合后有效样本比例被稀释
- 启示：**质量 > 数量**——筛选合适的 CFG range 比盲目混合更有效

## 五、创新点相关

### Q20: 你的核心创新是什么？和原 DefectDiffu (ECCV 2024) 有什么区别？

**预期追问概率**: ★★★★★（必问）

**回答要点**（按优先级排序）:

| 创新 | 级别 | 一句话 |
|------|:---:|------|
| **Feature Loss** | ★★★★★ | 在 PatchCore 特征空间加 Mahalanobis 约束，弥合"像素优化"与"特征检测"的 gap |
| **正常样本联合训练** | ★★★★★ | 30% 正常样本 + good 标签训练，模型同时掌握"生成缺陷"和"生成正常" |
| **闭环自适应生成** | ★★★★☆ | 检测反馈驱动生成预算分配，弱类别获得更多样本 |
| **前景/背景分离 Loss** | ★★★★☆ | 自适应权重取代硬截断，小缺陷自动获得更高优化权重 |
| **全通道 CFG** | ★★★☆☆ | 修复原 DiT 仅 3 通道 CFG 的 hack |
| **Dice Loss 掩码监督** | ★★★☆☆ | 解决前景/背景不平衡导致的掩码退化 |
| **一致性蒸馏** | ★★★☆☆ | 50 步 → 4 步，12× 加速 |
| **掩码条件生成** | ★★★☆☆ | 缺陷位置可控，随机掩码 → 指定位置生成 |

### Q21: 闭环反馈自适应的具体机制是什么？这个 idea 的来源？

**预期追问概率**: ★★★★☆

**回答要点**:
- 流程：生成 → PatchCore 评估 → 各类别 AUROC → 按误差反比分配下一轮预算 → 生成 → ...
- `budget[cls] ∝ (1 − AUROC[cls])`：AUROC 越低（检测越困难），分配越多生成预算
- 最少保证 min_per_class=10 张，避免某类完全得不到样本
- Idea 来源：受了主动学习 (Active Learning) 和 Hard Example Mining 的启发——模型应该"在哪里跌倒就在哪里爬起来"
- 实用性：对于 15 类 × 73 种缺陷的组合，手动调参不现实，自适应机制让系统自动找到瓶颈

---

### Q22: 掩码条件生成（Mask Condition）的原理？推理时掩码从哪来？

**预期追问概率**: ★★★☆☆

**回答要点**:
- 训练时：使用 GT 掩码作为输入条件 → 模型学习"这个位置的缺陷长什么样"
- 推理时：支持三种随机掩码模式：
  - `blob`：高斯斑点 → 模拟局部缺陷（如 color, cut）
  - `line`：线条 → 模拟划痕类缺陷
  - `noise`：随机噪声阈值 → 模拟不规则缺陷
- MaskEncoder（+35M 参数）：ConvNet 将空间掩码编码为 global + spatial 特征，注入 adaLN 和 token 序列

## 六、方法论与设计决策

### Q23: 为什么用 CLIP 而不是其他文本编码器（如 BERT、T5）？

**预期追问概率**: ★★★☆☆

**回答要点**:
- CLIP 是视觉-语言联合训练的——文本嵌入和图像嵌入在同一语义空间
- 对于"a photo of scratch bottle"这种视觉描述，CLIP 比纯文本模型更准确
- CLIP RN50 是轻量选择（1024-d），更大的 ViT-L/14 可能更好但推理更慢
- 原 DiT 论文也使用 CLIP（用于 ImageNet 类别名编码），保持一致性

---

### Q24: VAE 潜空间的 scaling factor 0.18215 是什么？为什么用这个值？

**预期追问概率**: ★★☆☆☆

**回答要点**:
- 这是 Stable Diffusion VAE 的标准 scaling factor
- VAE 编码后的 latent 大致有 unit variance（经过这个 scaling 后），有利于扩散模型训练
- 值来自于 SD VAE 的训练统计——是约定俗成的常数，不需要修改

### Q25: 为什么不用更大的分辨率（512×512）？

**预期追问概率**: ★★★☆☆

**回答要点**:
- DiT-XL-2 的预训练是在 256×256 上——换分辨率需要重新预训练或额外适配
- MVTec 原图 700-1024px，256×256 会导致细节损失（特别是 screw、metal_nut 这类细小缺陷）
- 代码已支持 `--imagesize 512`，但需要对应 checkpoint
- 提升分辨率是重要的后续方向——对检测性能可能有显著提升

## 七、局限性 & 未来工作（可能被追问）

### Q26: 你的方法有什么局限性？

**预期追问概率**: ★★★★★

**诚实回答**:
1. **分辨率限制**：256×256 对细微缺陷不够——预计 512×512 可显著提升 screw/metal_nut
2. **对文本 prompt 敏感**：缺陷描述词的微小变化可能影响生成结果——需要 prompt engineering
3. **类别间生成质量不均**：纹理类（wood, tile）生成质量低于结构类（bottle, capsule）
4. **需要 GT 掩码训练**：对于没有掩码标注的数据集无法直接训练（但推理时不需要）
5. **依赖预训练模型**：DiT + CLIP + VAE 三个大模型，部署成本高
6. **实验验证不完整**：合成正常样本对 PatchCore 的效果尚未实测（有推导无实测）
7. **一致蒸馏未完成**：加速采样的效果待验证

### Q27: 和现有方法（如 SDEdit, DALL-E, Stable Diffusion + ControlNet）比较如何？

**预期追问概率**: ★★★★☆

**回答要点**:
- vs. SDEdit / img2img：SDEdit 需要真实缺陷图作为起点（few-shot 场景没有），我们是 text-to-image
- vs. DALL-E / SD：通用模型不理解工业缺陷的微妙差异（"这个划痕是否影响产品质量"），领域微调是必要的
- vs. ControlNet：ControlNet 需要额外的控制信号（如边缘图），我们的 Cross-Attention 天然提供定位
- 核心差异：**同时生成图像 + 掩码**——这是为下游检测任务设计的，不是通用图像生成

## 十一、评估指标详解

> 答辩中可能会被问到"这些指标分别衡量什么""为什么选 AUPRO 而不是 XX""一个具体的 AUROC 值意味着什么"。以下用项目实际数据做解释。

---

### Q33: Image-level AUROC 是什么？怎么算的？

**一句话**：判断"这张图有没有缺陷"的能力。

**计算过程**：
1. 模型对每张测试图输出一个**异常分数**（PatchCore 是最大 Mahalanobis 距离，efficient_ad 是 teacher-student 差异）
2. 设定一个阈值 τ，分数 > τ 判为"有缺陷"，≤ τ 判为"正常"
3. 遍历所有可能的 τ，计算每个 τ 下的 TPR（真阳性率）和 FPR（假阳性率）
4. 以 FPR 为横轴、TPR 为纵轴画 ROC 曲线，曲线下面积 = AUROC

**值域与含义**：
- 1.00 = 完美分类
- 0.90+ = 工业可用
- 0.80-0.90 = 勉强可用，误报偏高
- 0.50 = 随机猜测（无效）

**本项目的实际数据**：

| 场景 | Image AUROC | 含义 |
|------|:---:|------|
| N=1 真实样本 | 0.8188 | 仅 1 张正常图训练，误报率高 |
| N=5 真实样本 | 0.8839 | 5 张正常图，可接受水平 |
| N=5 + 传统增强 | **0.9295** | 接近工业部署标准 |
| Full baseline | **0.9841** | 全部正常样本，几乎完美 |

**关键限制**：Image AUROC 只能告诉你"有没有缺陷"，不能告诉你"缺陷在哪"。一张图里如果只有一个 1 像素的缺陷，image AUROC 可以很高——它只需要识别这张图是异常的。所以还需要像素级指标。

---

### Q34: Pixel-level AUROC 是什么？和 Image 版本有什么区别？

**一句话**：判断"每个像素是否属于缺陷区域"的能力。

**计算过程**：
1. 模型输出一个**异常热力图**（与输入图像同分辨率），每个像素有一个异常分数
2. 与 GT 掩码逐像素比对——该像素在 GT 中是缺陷 → 正样本，不在 → 负样本
3. 对所有像素的异常分数计算 ROC 曲线，面积 = Pixel AUROC

**与 Image AUROC 的关键区别**：

| | Image AUROC | Pixel AUROC |
|------|------|------|
| 判断单元 | 整张图 | 每个像素 |
| 回答的问题 | "这张图异常吗？" | "异常在哪里？" |
| 受前景/背景不平衡影响 | 否 | **严重影响** |
| 本项目 Full baseline | 0.9841 | 0.9825 |

**为什么 Pixel AUROC 在本项目中通常很高（>0.90）**：
- 缺陷仅占图像 1-5%，背景像素占了 95%+
- 模型只需要把所有像素都判为"正常背景"就能拿到很高的 pixel AUROC——因为 95% 的背景像素确实不是缺陷
- 这就是为什么 pixel AUROC 在本项目中区分度很低——几乎所有配置都在 0.93-0.98，看不出差异

**实际数据**：
- N=1: Pixel AUROC 0.9284，看起来很高，但实际上模型可能把大量缺陷像素漏掉了——被 95% 的背景正确率给淹没了
- 这就是为什么还需要 AUPRO

---

### Q35: AUPRO 是什么？为什么它比 Pixel AUROC 更适合这个任务？

**一句话**：衡量"模型能不能把一个缺陷区域完整地、不中断地圈出来"——关注的是**每个缺陷区域**而非每个像素。

**计算过程**：
1. 将 GT 掩码按连通域拆分为多个**独立缺陷区域**（如一张图上有 3 条划痕 = 3 个 region）
2. 对每个 region，计算 PRO（Per-Region Overlap）：
   - 设定阈值 τ，模型预测的异常区域与 GT region 的交集面积 / GT region 面积
   - 遍历所有 τ，画出该 region 的 PRO 曲线
3. 对所有 region 的 PRO 曲线做平均 → 对每个 τ 取平均 overlap，得到整张图的 PRO 曲线
4. 将 PRO 曲线积分（AUC），再对所有 FPR ≤ 0.3 的部分做归一化 → AUPRO

**为什么 FPR ≤ 0.3 截断**：
- 工业部署中 FPR > 0.3 意味着 30% 的正常像素被误报，完全不可用——后面的曲线没有实际意义
- 截断后 AUPRO 更真实地反映"可用范围"内的定位精度

**与 Pixel AUROC 的关键区别**：

| | Pixel AUROC | AUPRO |
|------|:---:|:---:|
| 评估粒度 | 每个像素独立 | 每个缺陷**区域** |
| 对小缺陷敏感 | 否（被背景淹没） | **是** |
| 要求连通性 | 不要求 | **要求**（碎片化预测扣分） |
| 受 FPR 截断 | 否 | 是（FPR ≤ 0.3） |
| 区分度 | 低（0.93-0.98） | **高**（0.31-0.93） |

**本项目的实际数据**：

| 配置 | Pixel AUROC | Pixel AUPRO | 为什么差这么多？ |
|------|:---:|:---:|------|
| PatchCore Full baseline | 0.9825 | **0.9307** | 即使全量数据，AUPRO 也低于 pixel AUROC——因为连通性要求更严格 |
| PatchCore N=5 real only | 0.9532 | **0.8581** | 5 张正常样本下定位退化 |
| PatchCore N=5 + trad aug | 0.9610 | **0.8770** | 传统增强对 pixel AUROC 提升小（+0.008），但对 AUPRO 提升更明显（+0.019） |
| efficient_ad N=5 real only | 0.7290 | **0.3125** | AUPRO 直接掉到 0.31——监督模型在 few-shot 下定位几乎失效 |
| efficient_ad N=5 + ours | 0.7728 | **0.4448** | 合成缺陷让 AUPRO 提升 +0.132，是 image AUROC 增幅（+0.032）的 **4 倍** |

**最关键的观察**：合成缺陷对 AUPRO 的提升（+0.132）远大于 image AUROC（+0.032）。这正是因为——生成掩码提供了**准确的缺陷位置先验**，主要改善的是定位而非分类。AUPRO 能捕捉到这个差异，pixel AUROC 几乎捕捉不到（因为它被 95% 的背景像素稀释了）。

---

### Q36: 如果委员问"为什么 efficient_ad 的 AUPRO 比 PatchCore 低这么多？"

**回答**：
- PatchCore 是无监督方法，用 coreset 记忆了正常样本的全部特征分布，定位靠"哪里偏离了正常分布"
- efficient_ad 是监督方法，需要 `train/bad/` 中的缺陷样本来学习"什么算缺陷"。N=5 时只有 5 张正常 + 50 张合成缺陷，对于需要大量异常样本的监督模型来说远远不够
- 这恰好说明了两类方法的互补性——few-shot 场景下无监督方法（PatchCore）天然有优势；有足够合成数据时监督方法（efficient_ad）的增益更显著

---

### Q37: 三个指标的关系总结

```
Image AUROC  →  这张图有缺陷吗？           （粗粒度，判断是否报警）
Pixel AUROC  →  每个像素对不对？           （过粗，被背景像素稀释）
AUPRO        →  每个缺陷区域圈完整了吗？    （最真实反映工业需求）
```

**为什么本项目重点用 AUPRO**：
- 工业缺陷检测的核心需求是"找到缺陷在哪、圈出来、不要碎片化"
- pixel AUROC 会因为大量背景像素正确而虚高，看不出模型的真实定位能力
- AUPRO 直接惩罚"碎片化预测"（一个完整划痕被断成几截 → 每个 region 的 overlap 都低 → PRO 下降）
- 生成掩码质量的改善在 AUPRO 上体现最明显（+0.132 vs pixel AUROC 几乎不变）

## 十二、实验配置命名规则

> 答辩中展示实验结果表格时，委员可能直接问"N5_M50 是什么意思""为什么有的叫 real_only 有的叫 ours"。以下是完整的命名体系。

---

### Q38: 实验配置名称的组成规则是什么？

**核心变量**：

| 符号 | 含义 | 示例值 |
|------|------|------|
| **N** | 每类随机采样的真实正常样本数（从 `train/good/` 抽） | 1, 2, 5, 10, full(全部) |
| **M** | 每类生成的合成缺陷样本数（从 DefectDiffu 产出） | 10, 25, 50, 100 |

**命名模式**：`N{n}_M{m}` 或 `N{n}_real_only`

```
N5_M50   =  5 张真实正常样本 + 50 张合成缺陷样本
N1_real_only = 仅 1 张真实正常样本，不添加任何合成样本
full_real_baseline = 使用全部真实正常样本（上界参考）
```

**配置后缀含义**：

| 后缀 | 数据内容 | 谁读取 |
|------|---------|------|
| `real_only` | 仅真实正常样本（train/good/），无合成数据 | PatchCore ✓ / efficient_ad ✓ |
| `traditional_aug` | 真实正常 + 几何增强（旋转/翻转/颜色抖动，扩充 train/good/） | PatchCore ✓ / efficient_ad ✓ |
| `ours` | 真实正常 + DefectDiffu 合成缺陷（存入 train/bad/） | efficient_ad ✓ / PatchCore ✗（不读 train/bad/） |
| `M50` / `M100` | 真实正常（N 固定）+ M 张合成缺陷 | 同上 |

**CFG 消融实验的命名**（实验 5）：

| 配置 | CFG scale 范围 | 含义 |
|------|:---:|------|
| `cfg_low` | 1.0 - 1.5 | 弱引导，缺陷微弱模糊 |
| `cfg_medium` | 1.6 - 2.5 | 中等引导，推荐区间 |
| `cfg_high` | 2.6 - 4.0 | 强引导，缺陷过饱和 |
| `cfg_all` | 全部混合 | 混合所有 CFG 组 |

**五个实验的命名与目的**：

| 实验 | 目录名 | 研究问题 | 关键变量 |
|------|------|------|:---:|
| 实验 1 | `exp1_fewshot` | Few-shot 规模的影响 | N (1→2→5→10) |
| 实验 2 | `exp2_syn_count` | 合成数量饱和点 | M (10→25→50→100) |
| 实验 3 | `exp3_aug` | 扩散生成 vs 传统增强 | real / trad / ours |
| 实验 4 | `exp4_longtail` | 长尾缺陷覆盖率 | 仅 9 个困难类别 |
| 实验 5 | `exp5_quality` | CFG scale 消融 | cfg 分组 |

### Q39: "real_only" 和 "ours" 放在 train/good/ 还是 train/bad/？

这是实验中最重要的细节，直接影响 PatchCore 结果的理解：

```
                     train/good/              train/bad/
配置                  (PatchCore 读取)         (PatchCore 忽略)
──────────────────────────────────────────────────────────
real_only            N 张真实正常             空
traditional_aug      N 张真实 + ~45 张增强     空
ours                 N 张真实正常             M 张合成缺陷 ← PatchCore 读不到！
```

**关键事实**：PatchCore 的 `learning_type = ONE_CLASS`，训练时**仅扫描 `train/good/`**，完全跳过 `train/bad/`。

这就解释了为什么 PatchCore 上 `real_only` 和 `ours` 的 AUROC 几乎相等——两者的 `train/good/` 都是同样的 N 张真实正常样本，`train/bad/` 中的合成缺陷未被使用。`traditional_aug` 之所以能提升（+0.046），是因为它**增加了 `train/good/` 的样本数**，PatchCore 直接受益。

efficient_ad 是监督模型，读取 `train/bad/`，所以 `ours` 对它有效（+0.032 AUROC, +0.132 AUPRO）。

## 十三、检测模型对比：PatchCore vs efficient_ad

> 答辩中几乎必然被问到"为什么选这两个模型""它们的区别是什么""哪个更适合你的任务"。以下从机制层面解释本质差异。

---

### Q40: PatchCore 和 efficient_ad 的本质区别是什么？

**一句话**：PatchCore 问"这个跟正常像不像"，efficient_ad 问"这个跟缺陷像不像"。

| | PatchCore | efficient_ad |
|------|------|------|
| **学习范式** | 无监督（ONE_CLASS） | 监督 |
| **训练数据** | **仅** `train/good/`（正常样本） | `train/good/` + `train/bad/`（正常+缺陷） |
| **训练时看到过缺陷吗** | 没有 | 有 |
| **核心架构** | WideResNet-50 + Coreset 采样 | Teacher-Student 网络（PDN: Patch Description Network） |
| **异常分数** | Mahalanobis 距离：偏离正常分布的程度 | Teacher-Student 差异：学生无法复现教师对异常区域的特征 |
| **输出** | 异常热力图 | 异常热力图 |

---

### Q41: PatchCore 具体怎么工作的？

**训练阶段**：
1. 用 WideResNet-50 提取 `train/good/` 中所有正常样本的 layer2 + layer3 特征
2. Coreset 采样（贪心子采样，保留 1% 的 patch 特征作为 memory bank）
3. 存储这些特征 → 这就是"正常"的定义

**推理阶段**：
1. 提取测试图的 WideResNet 特征
2. 对每个 patch，在 memory bank 中找 k 个最近邻，计算 Mahalanobis 距离
3. 距离越大 → 越不像训练时见过的正常样本 → 越可能是缺陷

**为什么选它**：
- 工业异常检测的 SOTA baseline，被广泛引用
- 纯正常样本训练，适合"缺陷样本获取困难"的场景——正是本项目要解决的问题
- **Feature Loss 的创新直接建立在 PatchCore 之上**：Loss 使用的就是同一个 WideResNet-50 + Mahalanobis 距离

---

### Q42: efficient_ad 具体怎么工作的？

**训练阶段**：
1. 教师网络（预训练 WideResNet-101）提取图像的全局描述符
2. 学生网络（轻量 PDN）学习在正常区域复现教师的描述符，在缺陷区域产生差异
3. 需要 `train/bad/` 提供缺陷掩码——明确告诉模型"这些区域你不应该学教师"

**推理阶段**：
1. 教师和学生同时对测试图提取特征
2. 逐像素计算教师输出与学生输出的差异
3. 差异大 → 学生在这个区域复现失败了 → 此处可能是缺陷

**为什么选它**：
- 少数能利用 `train/bad/` 的监督模型——给合成缺陷一个"被用到"的机会
- 轻量（学生网络很小），推理速度快
- 与 PatchCore 形成**范式互补**：一个只看正常，一个看正常+缺陷

---

### Q43: 为什么 PatchCore 在 few-shot 下碾压 efficient_ad？

**实际数据（N=5）**：

| 指标 | PatchCore | efficient_ad | 差距 |
|------|:---:|:---:|:---:|
| N=5 real only Image AUROC | **0.8839** | 0.6537 | +0.230 |
| N=5 + traditional aug Image AUROC | **0.9295** | 0.6895 | +0.240 |
| N=5 + ours Image AUROC | 0.8882 | 0.6858 | +0.202 |
| N=5 real only Pixel AUPRO | **0.8581** | 0.3125 | +0.546 |
| N=5 + ours Pixel AUPRO | 0.8559 | **0.4448** | +0.411 |

**根本原因**：

- PatchCore 的 ONE_CLASS 在 few-shot 下是**天然优势**——它只需要知道"正常长什么样"，5 张正常样本就能构建一个粗糙但可用的 memory bank
- efficient_ad 的监督范式要求**同时见过正常和缺陷**——5 张正常 + 50 张合成缺陷对于监督学习来说远远不够，尤其是缺陷类型的覆盖率
- 这恰好说明**两类模型的互补关系**：few-shot 场景用无监督模型兜底，随着合成样本增多，监督模型的增益更大（AUPRO +0.132）
- 注意：PatchCore 的 `ours` 增益近乎为零是因为合成缺陷放在 `train/bad/` 里——这不是模型问题，是实验数据放置问题（见 Q14、Q39）

---

### Q44: 两个模型对 DefectDiffu 的意义是什么？

```
PatchCore →  验证"生成正常样本"的能力（Feature Loss 直接对齐 PatchCore 的特征空间）
efficient_ad → 验证"生成缺陷样本"的能力（合成缺陷的质量和多样性）
```

**为什么两个都跑**：DefectDiffu 同时生成图像和掩码，两个模型分别考察不同的输出维度：

| DefectDiffu 输出 | 被哪个模型验证 |
|------|------|
| 生成正常图像（condition="good"） | PatchCore 的 coreset 多样性 → AUROC ↑ |
| 生成缺陷图像（condition="scratch"） | efficient_ad 的缺陷模式学习 → AUROC ↑ |
| 生成缺陷掩码 | efficient_ad 的 pixel-level 监督 → AUPRO ↑↑ |

两个模型缺一个，都会遗漏 DefectDiffu 某类输出的价值验证。这是实验设计的完整逻辑。
